# ADR-011: REST Polling for Initial Dashboard Updates

**Status:** Accepted

## Context

The dashboard needs to display job status, queue activity, and execution history.

Real-time updates may improve the experience, but they introduce additional infrastructure and connection-management complexity.

## Decision

Use REST API polling for the initial dashboard.

Socket.IO may be introduced later for real-time updates without changing the underlying job state model.

## Consequences

- Simpler initial implementation.
- Easier debugging and infrastructure management.
- Polling frequency must be controlled to avoid unnecessary database load.
- Future real-time updates should reuse existing API and domain contracts.
