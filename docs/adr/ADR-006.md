# ADR-006: Transactional Outbox Pattern

**Status:** Accepted

## Context

A job creation request may require both a PostgreSQL transaction and publication of a message to Redis.

A failure between these operations could leave a job stored in PostgreSQL but never published to the queue.

## Decision

Use the transactional outbox pattern.

The API will write the business record and corresponding outbox event within the same PostgreSQL transaction.

A separate publisher process will deliver pending outbox events to the queue and track publication status.

## Consequences

- Reduces the risk of lost queue publications.
- Provides a durable record of pending events.
- Requires retry and failure handling in the publisher.
- Duplicate publication remains possible, so consumers must be idempotent.
