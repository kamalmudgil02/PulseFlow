# ADR-007: At-Least-Once Execution and Idempotency

**Status:** Accepted

## Context

Distributed job processing cannot safely assume that every job will execute exactly once. Workers can crash, messages can be redelivered, and network failures can create ambiguous outcomes.

## Decision

Adopt at-least-once execution semantics.

Job handlers must be designed to tolerate duplicate execution where possible.

Use idempotency keys and persisted execution state to prevent duplicate business effects.

Job attempts will be stored separately from the main job record.

## Consequences

- More reliable recovery after worker failures.
- Duplicate execution must be expected.
- Idempotency behavior must be documented for job handlers.
- External side effects require special handling, since database transactions cannot guarantee exactly-once behavior across external systems.
