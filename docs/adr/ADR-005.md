# ADR-005: Redis and BullMQ for Background Job Processing

**Status:** Accepted

## Context

PulseFlow requires asynchronous job processing, retries, delayed execution, queue management, and worker concurrency.

## Decision

Use Redis as the queue infrastructure and BullMQ as the initial job-processing library.

PostgreSQL remains the source of truth for job records and business state.

## Consequences

- Supports asynchronous job execution.
- Supports retries, delays, and concurrency controls.
- Redis availability becomes important to processing operations.
- Queue state and database state must be reconciled safely.
- Job handlers must tolerate duplicate delivery.
