# ADR-009: Authentication and API Key Strategy

**Status:** Proposed

## Context

PulseFlow needs authentication for dashboard users and programmatic access for applications submitting jobs.

## Proposed approach

Use separate authentication mechanisms:

1. Browser users authenticate through secure server-managed sessions.
2. External applications authenticate through workspace-scoped API keys.
3. API keys are stored as cryptographic hashes, not plaintext.
4. Keys have explicit permissions, revocation, and lifecycle controls.
5. Authorization is enforced at workspace and resource level.

## Consequences

- Supports both interactive and programmatic access.
- Requires secure key generation and storage.
- Requires careful session, CSRF, rate-limit, and permission handling.

## Open questions

- Should OAuth or social login be supported in the MVP?
- What API key permission scopes are required?
- Should API keys support expiration by default?

This proposal requires explicit approval before implementation.
